# 教材目录

本教材按依赖关系排列，而不是按“游戏功能”排列。进入下一章前，应通过当前章明确标出的“最低验收”或“第一次完成点”；推荐和扩展内容可以留到第二遍。若某章没有分层验收，则章末验收就是最低要求。

第一次阅读前，先看 [零基础前置知识](../references/beginner-prerequisites.md) 和 [术语表](../references/glossary.md)。画面出错、程序跑不起来时，查 [排错索引](../references/troubleshooting.md)——它按“你看到什么”把你送到正确的那一节。不要求你事先学过图形学，但需要会最基础的 C++：变量、函数、if、for、struct 和 vector。遇到陌生词不要跳过，先在术语表查它的“它是什么”和“它在一帧中的位置”。

## 每章的固定学习结构

章节正文会尽量按以下顺序展开：

1. 先建立直觉：这个概念解决什么实际问题。
2. 术语与数据：每个名词表示什么、数据存在哪里。
3. 数据流或推导：输入怎样一步步变成输出。
4. 具体算例：使用小数字手算，不只给最终公式。
5. 代码或伪代码：说明每行读取、修改、输出什么。
6. 常见错误与调试：错误画面是什么，怎样缩小范围。
7. 练习与验收：能运行、能解释、能故意制造并修复问题。

遇到“会使用但解释不清”的内容，应停下来补笔记，不以复制代码成功作为完成标准。

## 每章应该怎样读

推荐分三遍学习，不要求第一次就记住所有细节：

1. 第一遍读章首、各节标题和本章验收，先知道这一章解决什么问题。
2. 第二遍按顺序读正文，亲手重算数值例子，并画出输入到输出的数据流。
3. 第三遍实现练习。先预测结果，再运行；出错时按正文给出的顺序检查。

有些长章包含几个“部分”。**每一部分末尾都有一个「本部分检查点」**，写明这一步应该做出什么现象、应该能回答哪几个问题。通过它再继续下一部分；通不过就停在那里，不要往下读。

长章不必一次读完。按部分停下来是正常节奏：

| 篇幅 | 章 | 建议 |
| --- | --- | --- |
| 较短（约 500–700 行） | 04、05、06、07、08、16 | 可以一次读完一章 |
| 中等（约 700–900 行） | 01、03、09、10、11、12、13、14、17、19 | 一次读一个部分 |
| 较长（约 1000 行以上） | 02、15、18、20、21 | 一次读一个部分，中间务必停 |

若章首给出最低、推荐和扩展三条线，第一次只沿最低线学习。示例代码用于解释当前概念，不必第一次阅读时逐行背诵。

全书有三条反复出现的主线：

~~~text
几何主线：Vertex -> Triangle -> Fragment -> Pixel
帧主线：RenderSnapshot -> Queue -> Pass -> Framebuffer -> Present
游戏主线：Input -> Fixed Simulation -> Game Event -> Audio/Snapshot -> Render
~~~

读到高级章节时仍应能指出当前内容位于哪条主线、读取什么、修改什么、向下一步输出什么。
