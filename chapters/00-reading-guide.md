这一章不是图形学正文，而是告诉你怎样把后面的知识真正学会。图形学的难点通常不是某个公式本身，而是很多新名词、坐标空间和处理阶段同时出现。正确做法是一次只追踪一份数据。

## 本章导读

### 本章学习目标

完成本章后，应能：

1. 说出一章的学习循环是哪五步，以及为什么不能从敲代码开始。
2. 按本书的约定读懂一段 C++ 示例：类型名、变量名、函数名各代表什么。
3. 用五步法读一个公式，而不是背它。
4. 给一段图形代码的每个变量贴上 CPU 数据、GPU 资源、GPU 命令三种标签之一。
5. 写出一条包含现象、假设、证据、结论的有效学习记录。
6. 说出“最低、推荐、扩展”三层验收的区别，并知道第一遍只走最低线。

### 开始之前

- 图形学零基础没问题，但需要会最基础的 C++。自查清单见[零基础前置知识](../references/beginner-prerequisites.md)。
- 本章不需要配置任何图形环境。第 7 章才会用到 GLFW，那时再看[环境搭建](../plan/02-vscode-on-macos.md)。
- 第一次用 VS Code 从空文件夹建 C++ 工程，看[这一篇](../plan/03-first-cpp-project-in-vscode.md)。
- 每章顶部都有一条导航，里面的“术语表”和“可运行实现”会一直用到。

## 0.1 你将构建什么

渲染器读取游戏世界当前的物体、相机和灯光数据，生成一帧像素。后面学到游戏循环时，再把“世界更新”和“画出当前世界”分成两个明确步骤。

~~~text
输入 -> 更新游戏世界 -> 读取当前状态 -> 渲染器 -> GPU -> 屏幕
~~~

不要把“模型渲染”理解为先渲染 3D 再渲染 2D。模型顶点先从三维空间投影到屏幕坐标，再光栅化为二维像素；UI 是后续的独立绘制层。

## 0.2 一章的学习循环

每章按以下顺序学习：

1. 先读“概念”和“数据流”，不要急着输入代码。
2. 手写或口述关键公式与状态变化。
3. 完成“最小示例”，让结果先可见。
4. 完成一个“故意出错”实验，观察错误画面。
5. 按“验收”保存截图，在 plan/progress.md 记录结论。

术语不懂时先查 references/glossary.md。不要在不理解输入输出的情况下复制一大段 OpenGL 代码。

## 0.3 如何阅读代码示例

本书的 C++ 代码使用下列约定：

- 类型名首字母大写，例如 Vec3 和 Framebuffer；它表示“一个东西的结构”。
- 变量名小写，例如 width 和 color；它保存一个具体值。
- 函数名使用动词，例如 setPixel；它接收输入并完成一件事。
- struct 把相关数据放在一起；class 暂时可把它理解成“带函数的 struct”。
- 省略的错误处理会在正文说明；示例的目标是解释概念，不是可以直接发布的完整库。

~~~cpp
Vec3 position = {1.0f, 2.0f, 3.0f};
// Vec3 是三个浮点数的类型；position 是其中一个具体位置。
~~~

读每段代码前先问：输入是什么？输出是什么？它改变了哪一份数据？如果回答不出，就不要进入下一段。

## 0.4 代码与笔记的关系

chapters/ 是稳定的教材正文；exercises/ 是可失败、可重写的实验代码；plan/progress.md 是你的个人学习日志。一个理论结论至少要关联一个能运行的实验。

## 0.5 第一个练习

暂不配置 OpenGL。拿一张纸画出“模型顶点到屏幕像素”的路径，并标记你不确定的步骤。读完第 1 章后再修改这张图。

验收：能区分顶点、三角形、片段、像素、纹理和 Framebuffer，且知道它们不是同一个概念。

## 0.6 本书的调试原则

每个阶段都必须能回答：CPU 提交了什么？GPU 正在执行哪个 Shader？目标 Render Target 是什么？结果为何是这组像素？

## 0.7 如何阅读公式：一个完整示例

本书中的公式不是需要背诵的口令。遇到公式时，按下面顺序读：

1. 先找等号左边：我们最终要计算什么？
2. 再列出右边每个符号：它是一个数字、方向、位置还是矩阵？
3. 检查单位和范围：它表示米、Pixel、0 到 1，还是 -1 到 1？
4. 用一组简单数字手算一次。
5. 改变一个输入，预测输出怎样变化。

例如：

~~~text
newPosition = oldPosition + velocity * deltaTime
~~~

逐项解释：

- newPosition：这一帧结束后的新位置。
- oldPosition：这一帧开始时的位置。
- velocity：每秒移动多少距离以及移动方向。
- deltaTime：这一帧经过了多少秒。
- velocity * deltaTime：本帧实际移动的距离。

如果公式里的任意符号还无法用一句话解释，就先不要继续实现。

## 0.8 如何阅读图形代码

一段图形代码经常同时涉及 CPU 对象和 GPU 对象。阅读时给每个变量贴上三种标签之一：

~~~text
CPU 数据：普通 C++ 数组、结构体、文件数据
GPU 资源：Buffer、Texture、Program、Framebuffer
GPU 命令：bind、clear、draw、dispatch
~~~

再逐行问：

1. 这一行创建数据、修改数据，还是发命令？
2. 数据现在位于 CPU 内存还是 GPU 内存？
3. 这行之后谁会读取它？
4. 它何时被释放？

## 0.9 学习记录应该写什么

不要只记录“今天学了矩阵”。一条有效记录应包含：

~~~text
现象：立方体旋转时绕世界原点转圈
原假设：矩阵乘法顺序都一样
证据：交换 model = translation * rotation 后行为改变
结论：列向量约定下，右侧变换先执行
仍不懂：normal matrix 为什么要逆转置
~~~

这种记录会在后面的调试与性能章节直接复用。

## 0.10 每章真正完成的标准

“读完”不等于“学会”。进入下一章前，至少做到：

1. 能不看原文解释本章核心数据如何流动。
2. 能用简单数字手算一个例子。
3. 能指出一个错误实现会出现什么现象。
4. 能运行最小练习并保存结果。
5. 能回答最低验收对应的问题。

长章常把目标分为最低、推荐和扩展三层：

- **最低**：后续章节真正依赖的概念和最小实现，第一次必须完成。
- **推荐**：加深理解的完整版本，适合第一次有余力时继续。
- **扩展**：高级质量、性能或平台能力，允许第二遍再做。

如果章末列出许多练习，不表示每一项都是下一章前置条件。以章首完成点和章末分层验收为准。

## 0.11 常见错误：学习过程中的五种误区与修正

### 错误一：看到代码能运行，就认为已经理解

修正：关掉代码，口述输入、输出、数据存放位置和每一步原因。无法解释的部分仍需要学习。

### 错误二：一次引入太多功能

修正：先只画纯色，再加深度，再加 Texture，再加光照。每次只增加一个可观察变量。

### 错误三：遇到黑屏就随机改参数

修正：从最终 Framebuffer 反向检查目标、Pass、Shader、Vertex 和资源。每次提出一个可以被证据验证的假设。

### 错误四：只收藏资料，不做手算和实验

修正：每个公式至少用简单数字算一次；每个渲染状态至少故意关错一次并记录现象。

### 错误五：为了赶进度跳过验收

修正：没有通过最低验收就不要进入下一章。图形学知识依赖很强，前面的空间或插值概念不清楚，会在后面表现为难以定位的 Shader 和阴影问题；推荐和扩展验收则可以留待第二遍，避免一次引入太多变量。
